# Shinhan Native Trader

신한투자증권 Indi ActiveX를 사용하는 **C# .NET Framework 4.8 / x86 Windows 프로그램**입니다. 종목·일봉·현재가·잔고 조회와 실제 시세 기반 모의 자동매매를 제공합니다. **실주문은 C# 및 기존 Python API 모두 차단됩니다.** 현재 공식 주문 명세와 실제 Windows Indi 서버 검증이 확보되지 않았으므로 실계좌 자동매매 완성판으로 배포하지 않습니다.

## 1.4.2 — 현재가 조회 전용 TR과 거래시각 검증 분리

사용자 1.4.1에서 종목4,330건 수신·일반주식2,401개 처리가 확인됐습니다. 이어서 `SC rid=7`도 오류상태0으로 수신됐지만 파서가 실패했습니다. 기존 로그가 실패한 필드를 숨겨 실제 원인을 구분하지 못했습니다. 공식 Helper의 SC 코드1/시각2/가격3은 기존 인덱스와 일치하므로 번호 오류로 단정하지 않습니다.

- **현재가 조회** 버튼은 공식 `TR_1110_11`의 입력0 종목코드·출력24 현재가를 사용합니다. 결과를 진단 로그뿐 아니라 화면 상태에도 표시합니다.
- 해당 TR은 종목코드 응답과 체결시각을 제공하지 않습니다. 요청번호를 대조하고 가격을 검증하되 **가격 표시 전용**으로 처리하며 자동매매에 사용하지 않습니다.
- 별도 SC 가격은 종목·가격이 유효하고 체결시각을 검증한 경우에만 모의매매의 장중·신선도 검사를 통과할 수 있습니다. 시각이 없거나 형식이 다르면 가격 표시만 허용합니다. PC 수신 시각을 거래시각으로 대체하지 않습니다.
- 파싱 오류는 실패한 필드를 명시하고, 현재가의 공개 필드만 제한된 길이로 기록합니다. 계좌·암호는 계속 가리며 공급자 예외 원문을 저장하지 않습니다.

공식 조회 리소스의 해시와 필드 대조, 잔고 미체결3/4에 관한 자료 간 충돌은 [조회 계약 기록](docs/INDI_QUERY_CONTRACT.md)에 정리했습니다. **수정 후 현재가·일봉·잔고의 실제 반환값과 HTS 대조는 아직 미검증입니다.**

## 1.4.1 — 도착한 응답을 중단 판정으로 버리던 오류 수정

사용자 1.4.0 로그에서 앱과 Indi 모두 `High(12288)`, `RequestData rid=3`, `NATIVE ReceiveData rid=3`이 확인됐습니다. 통신·이벤트 전달은 이 요청에서 작동했지만, 앱이 응답 도착 전에 `GetErrorState=2`만으로 중단해 응답을 버렸습니다.

- 양수 요청번호를 받으면 일치하는 `ReceiveData`를 기다립니다. 요청 직후 진단 숫자로 접수 실패를 판정하지 않습니다.
- 공식 OCX는 요청할 때 응답 상태를 지우므로 대기 중에는 오류 코드·문구가 비어 있어도 상태2가 나옵니다. 성공/오류 상태는 콜백이 발생하기 전에 기록됩니다. 콜백 안에서 상태와 데이터를 복사하고, 요청번호가 일치한 응답만 판정합니다.
- 재진입 콜백, 이전/중복 응답, 실제 오류 응답, 잘못된 데이터와 타임아웃 검증을 유지합니다. 오류 응답을 빈 잔고로 성공 처리하지 않습니다.

로컬 C#189개 검증과 Python17개 테스트가 통과했습니다. **사용자 PC에서 종목 행 파싱과 현재가·일봉·잔고 조회값의 HTS 대조는 아직 확인되지 않았습니다.** 최신 Windows 빌드와 다운로드는 [PR #1](https://github.com/na999jason-sketch/shinhan-autotrader/pull/1)에 기록합니다. 실주문은 잠금 상태입니다.

## 1.4.0 — Indi 프로세스와 Windows 메시지 권한 맞춤

공식 배포 OCX를 추출해 확인한 결과, `GI004`는 `WM_COPYDATA`의 `SendMessageA` 반환값이0 이하인 경로에서 설정됩니다. 오류 문구만으로 조회 파일 파싱 문제라고 단정할 수 없었습니다. 공식 `giexpertstarter.exe`는 관리자 권한을 요구하고, 그 자식 프로세스는 권한을 상속합니다. 낮은 권한의 앱이 높은 권한의 Indi로 보내는 메시지는 Windows UIPI에 의해 거부될 수 있습니다.

- EXE에 `requireAdministrator` manifest를 포함해 공식 Indi 시작기와 실행 권한을 맞춥니다. **실행 시 Windows 권한 확인 창이 나타납니다.** 실주문 잠금은 유지됩니다.
- 로그에 앱/Indi 수신 프로세스의 실제 integrity level과 요청 직후 Win32 오류를 기록합니다.
- 공식 OCX에서 확인한 양수 요청 ID 규칙을 적용해 반환값0을 대기 요청으로 취급하지 않습니다.
- CI는 실제 고권한 수신 프로세스와 별도 고/저권한 송신 프로세스로 `WM_COPYDATA` 성공과 접근거부5를 검증합니다. EXE 안에 관리자 권한 manifest가 실제로 포함됐는지도 검사합니다.

1.4.0 사용자 로그에서는 양수 요청번호와 실제 이벤트 수신까지 확인됐습니다. 위 1.4.1은 그 응답을 버리던 앱 오류를 수정합니다. 공식 배포 파일 해시와 분석 근거는 [실제 OCX 통신 분석](docs/INDI_IPC_EVIDENCE.md)에 기록했습니다.

## 1.3.0 — GI004 요청 파싱 오류에 대한 수정

1.2.0의 실제 실행에서 `RequestData` 직후 `GI004: 조회 데이터 파싱 오류 입니다`가 확인됐습니다. 이벤트 수신 이전의 요청/컴포넌트 초기화 경로를 수정합니다.

- C# 예제의 초기화 순서에 맞춰 각 OCX에서 `StartIndi("", "", "", 설치경로)`를 호출합니다. 설치된 32비트 OCX 등록 위치에서 `giexpertstarter.exe`를 찾으며 앱이 사용자 암호를 전달하거나 저장하지 않습니다.
- 문자열 반사 호출과 강제 invariant LCID를 제거하고, 확인한 생성 Interop의 IID/DISPID/VARIANT/Int16 형식에 맞춘 읽기 전용 COM 호출을 사용합니다.
- 초기화가 끝난 뒤 정상 UI 메시지 처리 순서로 첫 요청을 넘깁니다. `SetQueryName` 직후 `GetQueryName`을 대조해 다른 쿼리 상태로 요청하지 않습니다.
- `Visible=False`는 비시각 ActiveX의 정상 속성일 수 있으므로 단독 원인으로 취급하지 않습니다. 확인 근거 없이 기존 Indi 설치나 로그인 설정을 바꾸도록 요구하지 않습니다.

합성 COM 검증은 신한 서버의 실제 응답 성공을 대신하지 않습니다. **1.3.0에서 실제 신한 수신 성공은 아직 확인되지 않았습니다.**

## 1.2.0 — 실제 Windows 수신 실패에 대한 수정

사용자의 Windows 실행에서 `stock_mst rid=0` 뒤 `ReceiveData`가 없고 20초 후 중단되는 문제가 재현됐습니다. 같은 PC의 Indi/Helper 조회는 정상이라는 확인을 반영했습니다. 이전 CI 성공은 이 실제 수신 문제의 해결 증거가 아닙니다.

- 이벤트 연결을 초기화 이후의 호출에서 `AxHost.AttachInterfaces/CreateSink/DetachSink` 수명 단계로 옮깁니다. 생성된 AxInterop 래퍼와 같은 단계에서 구독·해제를 수행합니다.
- 설치 typelib에서 확인한 `GetCommState/GetErrorState/GetErrorCode/GetErrorMessage`만 조회해 요청 직후·실패·타임아웃의 원인을 기록합니다. 계좌·암호는 로그에서 가립니다. 통신상태 숫자만으로 로그인 실패라고 단정하지 않습니다.
- null·bool·소수·문자열을 요청번호 0으로 변환하지 않습니다. 정수 ID 0의 공식 의미는 미확인이라 실제 콜백 또는 명시적 공급자 오류로 판정합니다.
- 첫 정상 응답 전에는 연결 완료로 표시하지 않으며, 재진입 성공/즉시 실패 상태를 대기 문구로 덮어쓰지 않습니다. 창 제목에 `1.2.0`을 표시합니다.
- CI에 생산 구독 코드를 직접 사용하는 네이티브 C++ COM 이벤트 테스트를 추가합니다. 이는 실제 COM 콜백을 검증하며 신한 OCX/서버 수신을 대신하지 않습니다.

근거와 남은 검증은 [수신 장애 분석](docs/INDI_RECEIVE_DIAGNOSIS.md)에 기록했습니다. **이 수정본의 실제 신한 수신 성공은 아직 확인되지 않았습니다.**

## 실행과 빌드

1. GitHub Actions의 성공한 `Build and test Shinhan Native Win32` 실행에서 `ShinhanNativeTrader-Win32` 아티팩트를 내려받습니다. 검증 기록은 `validation-reports`에 있습니다.
2. Windows에서 공식 신한 Indi 국내주식 ActiveX를 설치하고 로그인합니다. 설치/로그인 방법은 신한 공식 안내를 따릅니다. 이 프로그램은 자격증명을 보관하거나 자동 로그인하지 않습니다.
3. EXE를 실행하고 `Indi 연결·종목 조회`로 실제 `stock_mst` 응답을 확인합니다. 일봉/현재가/실제 잔고 조회는 각각 별도로 실행합니다. 계좌 암호는 잔고 요청 직후 화면에서 지웁니다.
4. `전략·투자원금` 탭에서 설정을 저장한 뒤 `전체 스캔·모의매매 시작`을 누릅니다. 보유 감시는 스캔 완료 이후에도 계속됩니다. 중단 후에는 `모의 보유 감시 재개`로 감시만 재개할 수 있습니다.

Visual Studio Build Tools와 .NET Framework 4.8 targeting pack이 있는 Windows 개발자 명령 프롬프트:

```bat
msbuild ShinhanNativeTrader.csproj /t:Rebuild /p:Configuration=Release /p:Platform=x86 /p:PlatformTarget=x86 /warnaserror
```

PowerShell에서 COM 없이 C# 테스트 실행:

```powershell
$p = Start-Process .\bin\Release\ShinhanNativeTrader.exe -ArgumentList '--selftest --selftest-report reports\native-tests.txt' -Wait -PassThru
Get-Content reports\native-tests.txt
if ($p.ExitCode -ne 0) { throw 'Native tests failed' }
python scripts/verify_x86.py bin/Release/ShinhanNativeTrader.exe
python -m unittest discover -s tests -v
```

기존 `app.py`, `build_exe_win32.bat`는 레거시 Python 프로그램입니다. 위 C# EXE 빌드와 구분하십시오. Python 주문 어댑터를 직접 호출해도 요청 전에 예외를 발생시킵니다.

## 변경된 구조

- `IndiCom.cs`: 설치된 typelib의 outgoing IID/DISPID/인자형을 탐색하여 이벤트를 연결합니다. 고정 IID와 DISPID를 제거하고 동일 STA, ActiveX 수명, delegate 보관과 해제를 관리합니다. COM 실행부·요청 상태기계·응답 파서를 분리했습니다.
- `IndiRequestCoordinator`: 요청번호 대조, 요청 반환 전 재진입 콜백 버퍼 복사, 중복/다른 요청 응답 무시, 오류·20초 타임아웃 차단을 담당합니다. 잘못된 숫자·필드·중복 종목은 성공 응답으로 취급하지 않습니다. COM 실행부는 조회 TR 다섯 개만 허용합니다.
- `Strategy.cs`: 이동평균·고점돌파·거래량 조건, 손절·익절·고점 추적손절, 원금 배분과 비용률, 한국시간 장 운영시간을 제공합니다. 전략 기간에 맞는 일봉 수를 요청합니다.
- `TradingEngine.cs`: 모의 주문·체결번호, 부분체결, 거절·취소·만료, 현금 예약, 매도가능수량, 최대 보유수, 중복 방지와 상태 검증을 담당합니다. 주문 요청을 체결로 추정하지 않습니다.
- `Program.cs`: 전략/원금 편집, 실제 조회와 모의 잔고/주문 화면, 전체 종목 순차 스캔, 보유종목 우선 조회를 연결합니다. 매수는 당일 일봉 신호와 별도 최신 현재가, 신호 기준가 대비 3% 이내 조건을 요구합니다. UI 모의체결은 즉시 전량 체결이며 부분체결·미체결 경로는 엔진 테스트로 검증합니다.

모의 매수금액은 모의 가용현금과 예약금을 기준으로 검증합니다. **투자원금·모의현금·증권사 잔고/예수금은 실제 주문가능금액이 아닙니다.** 실제 체결/미체결 조회, 주문가능금액 TR, `AA/AB/AD/AE` 실시간 계좌 이벤트는 구현·실서버 검증이 남아 있습니다.

## 저장과 재시작

`%LOCALAPPDATA%\ShinhanNativeTrader\paper-v2.xml`에 모의 원금·현금·전략·주문·체결·보유고점을 저장합니다. 임시 파일 flush 후 원자적으로 교체하며, 다른 실행 프로세스의 동시 쓰기를 차단합니다. 저장 실패·손상된 파일은 자동 거래를 막습니다. 파일을 무시하거나 초기화해 계속 매매하지 않습니다.

재시작 시 미완료 모의 주문은 `NeedsReconciliation`이 되고 예약금/수량을 유지합니다. 화면의 `재시작 모의 미체결 취소·예약금 해제`로 **모의 주문만** 취소한 뒤 다시 시작하십시오. 실제 증권사 주문을 취소하거나 대사하는 기능이 아닙니다. 이전 버전 `paper_trades.csv`는 고점/미체결 증거가 부족해 자동 변환하지 않으며 그대로 보존합니다.

## 검증 범위

CI는 Windows 2022에서 .NET 4.8 x86 빌드, PE32/CLR 32BITREQUIRED 확인, C# 단위·모의매매 테스트, Python 회귀 테스트를 실행합니다. 설치된 Indi OCX나 로그인 계좌는 사용하지 않습니다.

사용자 로그에서 실제 Windows Indi 종목4,330건 파싱·일반주식2,401개 처리까지 확인됐습니다. 현재가/일봉/잔고 조회값의 HTS 일치·연결 복구·공식 주문 필드·체결/미체결/주문가능액 대사는 미검증입니다. 시세 시각 `HHMMSS`는 날짜를 포함하지 않으므로 당일 시세임을 독립적으로 증명하지 못합니다. 휴장일 달력, 호가/유동성, 지연/슬리피지 및 전략 수익성도 검증되지 않았습니다. 전략은 예시이며 투자 성과를 보장하지 않습니다.
