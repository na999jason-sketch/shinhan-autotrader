# Shinhan Native Trader 2.0

신한투자증권 Indi ActiveX를 사용하는 **C# .NET Framework 4.8 / x86 Windows 실계좌 프로그램**입니다. 실제 계좌의 보유 종목·현재가·평균단가·평가손익, 예수금·주문가능금액과 증권사 주문 조회를 표시합니다. 종목 발굴과 부재중 장중 운영을 지원합니다.

**신규·정정·취소 주문 코드는 포함돼 있지만 현재 배포물의 실주문 게이트는 잠금 상태입니다.** 현재 주문 명세, 주문가능금액의 의미, 체결·미체결·재시작 대사가 실서버에서 검증되지 않았습니다. 실행·운용한도 저장·부재중 운영 시작만으로 주문이 활성화되지 않으며, 내일 실거래가 가능하다고 보장하지 않습니다.

2.0 실행 프로그램은 가상 잔고·가상 체결을 생성하지 않으며 이전 `paper-v2.xml`도 읽지 않습니다. 과거 엔진·테스트는 [legacy/paper](legacy/paper/README.md)에 보존하고 EXE 컴파일 대상에서 제외했습니다.

## 실행

1. [PR #1](https://github.com/na999jason-sketch/shinhan-autotrader/pull/1)에 기록된 **2.0 Windows 빌드**의 `ShinhanNativeTrader-Win32` ZIP을 내려받아 압축을 풉니다. 빌드·검증 보고서는 같은 실행의 `validation-reports`입니다.
2. Windows에서 공식 신한 Indi 국내주식 ActiveX를 설치하고 로그인한 뒤 EXE를 실행합니다. EXE는 공식 시작기와 권한을 맞추기 위해 Windows 관리자 권한 확인을 요청합니다.
3. `Indi 연결·종목 조회`로 종목 수신을 확인합니다. `전략·운용한도` 탭에서 전략과 **실계좌 운용한도**를 확인하고 `전략·운용한도 저장`을 누릅니다. 한도의 초기값은0입니다. 설정값은 증권사 현금100% 주문가능금액이나 잔고를 대신하지 않습니다.
4. 계좌번호와 계좌암호는 프로그램에만 입력하고 `실계좌 조회·감시`를 누릅니다. `실계좌 잔고·손익`과 `주문·체결` 탭의 실제 조회 결과를 확인합니다. 화면 암호는 지워지고 조회 세션은 메모리에 유지됩니다. 계좌·암호를 채팅·이슈·PR에 적지 마십시오.
5. `부재중 운영 시작`을 누르면 장중 스캔과 계좌 정보 갱신을 진행합니다. 퇴근 후 화면과 `보고서 폴더`에서 날짜별 보고서를 확인할 수 있습니다. 실주문 잠금이 표시되면 주문 전송은 이루어지지 않습니다.

자세한 확인 순서와 실제 Windows에서 남은 항목은 [사용자 검증 안내](docs/USER_WINDOWS_VALIDATION.md)를 참조하십시오.

## 부재중 운영

한국시간 **평일09:00~15:20**에 전체 종목을 순차 분석하고, 한 차례 스캔을 마친 뒤20분 후 다시 스캔합니다. 계좌 조회는60초 간격으로 대기열에 넣고 보유 시세도 주기적으로 갱신합니다. 단일 요청의 응답을 기다리는 구조이므로 실제 갱신 간격은 응답 지연에 따라 달라집니다. 장외에 켜두고 `부재중 운영 시작`을 누르면 다음 평일 장 운영시간까지 기다립니다. 휴장일 달력은 아직 연동하지 않았습니다.

부재중 운영 중 자동 절전을 억제하고 `운영 중단`·종료 시 해당 요청을 해제합니다. PC 전원과 네트워크, Indi 로그인 상태가 유지돼야 합니다. 수동 절전·재부팅·로그오프나 Indi 인증 만료 후 자동 로그인·자동 주문 재개는 제공하지 않습니다. `운영 중단`과 전략 저장은 계좌 세션도 해제하므로 다시 운영하려면 계좌암호를 입력해 `실계좌 조회·감시` 후 `부재중 운영 시작`을 누릅니다.

응답 오류·시간 초과·저장 실패·계좌 불일치가 발생하면 자동 처리를 중단합니다. 불명 주문은 추가 주문을 차단하며, 상태를 지우거나 같은 주문을 자동 재전송해 계속 진행하지 않습니다. 감시 중5분 간격과 스캔 완료·중단·종료·거래일 변경 때 보고서를 남깁니다. 보고서의 조회 시각을 확인해 당일 새 데이터와 이전 응답을 구분하십시오.

## 잔고와 손익

- 기존에 보유한 종목도 새로 매수한 종목과 같은 보유 감시 대상입니다. 종목 발굴 후보 목록과 관계없이 실제 잔고에 들어 있는 현물 보유에 설정한 손절·익절·추적손절을 적용합니다. 조건을 충족하면 매도 대상으로 판단하고, 충족하지 않으면 보유를 유지합니다.
- 매도 후 신규 매수금액은 증권사의 현금100% 주문가능금액과 종목별 가능수량을 다시 조회해 정합니다. 매도 접수 금액을 가용자금으로 더하거나 모든 기존 보유가 팔릴 때까지 신규매수를 일괄 차단하지 않습니다.
- 현재가·평균단가·보유수량은 증권사 응답을 사용합니다. 수량·단가·시각이 없으면 미확인으로 표시합니다.
- 평가금액은 `현재가 × 수량`, 매입금액은 `평균단가 × 수량`, 평가손익은 두 금액의 차이입니다. 평가수익률은 매입금액 대비 비율입니다. **수수료·세금은 제외**하므로 HTS의 비용 포함 손익과 다를 수 있습니다.
- 실제 체결·비용 자료가 없는 실현손익은 추정하지 않습니다. 주문 접수와 체결을 구분하며, 체결번호가 없는 누적 조회 행을 개별 체결로 더하지 않습니다.
- 수동 현재가 조회 `TR_1110_11`은 가격만 제공하며 체결시각을 제공하지 않습니다. 표시용 가격과 거래에 사용할 수 있는 장중 시세를 구분합니다. PC 수신 시각을 체결시각으로 대신하지 않습니다.

## 저장과 복구

기본 데이터 위치는 `%LOCALAPPDATA%\ShinhanNativeTrader`입니다.

| 파일 | 내용 |
| --- | --- |
| `live-settings-v1.xml` | 실계좌 운용한도, 전략 설정, 확인된 시세에서 관측한 보유 고점 |
| `live-orders-<계좌키>.xml` | 주문 중복방지 키, 거래일, 계좌 식별 지문과 확인된 주문·체결·정정·취소 상태 |
| `reports\<계좌키>\account-report-yyyyMMdd.csv` | 실제 계좌 조회·평가손익·증권사 주문 스냅샷·프로그램 주문 기록과 조회 시각 |
| `diagnostics.log` | 민감정보를 가린 진단 기록 |

계좌키는 계좌번호를 그대로 쓰지 않는 식별값입니다. 계좌 비밀번호는 실행 중 인증된 세션 메모리에만 보관하며 디스크에 저장하지 않습니다. 보고서에는 계좌번호·암호를 넣지 않습니다. 보고서 자체에는 보유 수량·가격 등 투자 정보가 있으므로 공유 전 내용을 확인하십시오. `보고서 폴더` 버튼으로 현재 계좌의 보고서 위치를 열 수 있습니다.

설정·주문 저널은 임시 파일을 flush한 뒤 원자적으로 교체하고 동시 쓰기를 막습니다. 재시작 시 미완료 주문은 불명 상태로 차단하며, 증권사 주문·체결·미체결 대사 없이 예약금/수량을 해제하거나 주문을 다시 전송하지 않습니다. 과거 가상 계정 파일은 변환·삭제하지 않고 보존합니다.

## 주문 인터페이스와 검증 범위

확보한 공식 설치 자료에서 `SABA101U1` 신규, `SABA102U1` 정정·취소, `SABA602Q1` 현금100% 주문가능금액, `SABA415Q1` 종목별 주문가능수량, `SABA231Q1` 주문 스냅샷을 대조했습니다. [주문 계약 기록](docs/INDI_LIVE_ORDER_CONTRACT.md)에 리소스 해시와 확인되지 않은 기본값·시장 규칙을 정리했습니다. 현물 실시간 계좌 이벤트는 `AA`·`AD`이며 `AB`·`AE`는 파생상품용입니다.

사용자1.4.x 화면에서 종목4,330건·일반주식2,401개, 수동 현재가 응답, 일봉45개 반복 수신, 잔고2건과 스캔262개·후보2개를 확인했습니다. 이는 **실제 응답 수신과 파싱·표시의 증거**이며 HTS 값 일치나 주문 체결 검증을 뜻하지 않습니다. 2.0의 새 주문·무인 운영 경로를 실제 서버에서 검증한 결과도 아닙니다.

Windows CI는 .NET4.8 x86 빌드와 내장 관리자 manifest, 계좌 파서·주문 상태·무인 일정·보고서 테스트, 생산 어댑터를 사용하는 합성 네이티브 COM, 실제 Windows 프로세스 간 UIPI, 기존 Python 회귀·주문 차단을 검사합니다. 신한 OCX·인증 계좌·실제 주문은 사용하지 않습니다. **2.0 최종 빌드 결과와 EXE 링크는 PR에서 확인하십시오.** 이전 버전의 빌드 성공을2.0 검증으로 취급하지 않습니다.

현재 서버의 주문 필수값·가격 단위·시장 라우팅, 현금100% 금액의 비용/예약금 반영, 실제 부분체결·취소확정·연결 복구, 스냅샷의 완결성, 누락 이벤트 대사와 시세 날짜는 미검증입니다. 이 조건을 설정값이나 사용자 승인만으로 검증 완료로 바꾸는 기능은 없습니다.

## 개발 빌드

Visual Studio Build Tools와 .NET Framework4.8 targeting pack이 있는 Windows에서 실행합니다.

```bat
msbuild ShinhanNativeTrader.csproj /t:Rebuild /p:Configuration=Release /p:Platform=x86 /p:PlatformTarget=x86 /warnaserror
```

```powershell
$p = Start-Process .\bin\Release\ShinhanNativeTrader.exe -ArgumentList '--selftest --selftest-report reports\native-tests.txt' -Wait -PassThru
Get-Content reports\native-tests.txt
if ($p.ExitCode -ne 0) { throw 'Native tests failed' }
python scripts/verify_x86.py bin/Release/ShinhanNativeTrader.exe --require-admin
python -m unittest discover -s tests -v
```

루트 C# 소스만 EXE에 컴파일합니다. 기존 `app.py`와 Python 배치 빌드는2.0 C# EXE의 진입점이 아닙니다. 과거 수신 장애와 수정 근거는 [OCX 통신 분석](docs/INDI_IPC_EVIDENCE.md), [조회 계약](docs/INDI_QUERY_CONTRACT.md), [검증 보고서](TEST_REPORT.txt)에 남아 있습니다.
