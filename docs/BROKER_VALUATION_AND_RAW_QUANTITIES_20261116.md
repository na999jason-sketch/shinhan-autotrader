# 증권사 평가값과 당일 매수 잔고 수량

2.2.14는 증권사 직접 평가값을 읽고 가격 수익률을 구분하며, 아직 해결되지 않은 수량 문제의 원본 근거를 보존합니다.

## 실제 보고서에서 확인한 것

사용자가 제공한11월16일09:31 KST 보고서의 증권사 당일 주문에는 `241520` 매수18주·누적체결18주·평균체결가8,160원·미체결0이 기록됐습니다. 검증된54출력 프로필과 정상 접수 상태 대조가 있고, 프로그램 저널도 같은 매수를18주 `Filled`로 기록했습니다. 이는 앞선 접수 로그보다 진전된 **전량체결 증거**입니다.

같은 보고서의09:30:58 잔고 응답은 MO4 잔고수량0·MO10 주문가능수량18·MO11 미체결수량0·평단8,160원입니다. 표시 현재가8,100원과 평단의 가격 차이는 약−0.74%이나, 프로그램은 수량0에 가격을 곱해 평가금액0·손익0·수익률미확인을 표시했습니다. 현재 자료에는 추가 수량 필드나 증권사의 종목별 직접 평가값이 없어, 수량 차이의 원인은 아직 확정할 수 없습니다. 실제 원본 파일이나 계좌·주문 식별자는 저장소에 포함하지 않습니다.

## 직접 평가값과 표시

| 범위 | 필드 | 용도 |
|---|---|---|
| 종목 | MO18 | 증권사 평가금액 |
| 종목 | MO19 | 증권사 미실현손익 |
| 종목 | MO20 | 증권사 손익률 |
| 계좌 | SO15/18/19/22 | 매입금액·평가금액·미실현손익·손익률 |

[신한 위탁잔고 안내](https://file.shinhansec.com/help/goodi_slite/5401.htm)는 체결 기준 평가금액·손익률을 설명합니다. 직접 응답값은 계산값과 출처를 구분해 보존합니다. 비용 포함 여부를 프로그램이 임의로 단정하지 않습니다.

종목 수익률은 증권사 MO20이 있으면 해당 조회시점 값을 `(증권사)`로 표시합니다. 새 실시간 가격이 들어와도 증권사의 이전 조회 수익률을 그 가격으로 계산한 값처럼 표시하지 않습니다. 출처와 응답 UTC는 셀 설명과 CSV에 기록합니다. MO20이 없으면 `(현재가−평균단가)/평균단가×100`을 `(단가)`로 구분합니다. 이 가격 비교는 수량·체결·계좌 전체 수익률의 증거가 아닙니다. 평균단가·가격 누락이나 계산 범위 초과는 미확인입니다.

수량 대사 중 직접 증권사 값도 없는 계산 금액은 미확인으로 표시합니다. 계좌 전체 수익률을 단가 비교로 만들거나, 불확실한 수량을 이용해 주문 예산을 늘리지 않습니다.

## 수량 원본과 남은 문제

같은 정상 콜백에서 다음 선택 필드를 숫자 또는 미확인으로 보존합니다. 새 요청이나 주문을 발생시키지 않습니다.

| 필드 | 의미 |
|---|---|
| MO4 | 기존 원본 잔고수량 |
| MO5/6 | 전일/당일 매도 미결제 |
| MO7/8 | 전일/당일 매수 미결제 |
| MO9 | 결제일수량 |
| MO10/11 | 주문가능수량/미체결수량 |
| MO12/13 | 해당 잔고 콜백의 평균단가/현재가 |
| MO32 | 평가잔고수량 |

CSV는 매매기준 SI3=1과 보통잔고 SI3=5를 별도 표로 기록하고 요청·수신 UTC를 보존합니다. MO12/13은 콜백 당시 숫자를 따로 복사하므로 이후 SC 현재가가 바뀌어도 원본 평가금액과의 대조에 쓰는 가격이 바뀌지 않습니다. 누락·비정상 선택 숫자는 미확인, 명시적인0은0입니다. 기존 필수 수량 검사는 유지합니다.

**MO32를 현재 매도 가능한 보유수량으로 대체할 공식 필드 규약은 확인하지 못했습니다.** 주문가능수량18이나 전량체결18만으로 원본 잔고0을 덮어쓰지 않습니다. 현재 보유수량의 확정, 수량 보류 해소와 해당 종목 자동매도는 남은 문제입니다. 문서화된 AD6 당일잔고도 실제 관측 근거 없이 만들어 쓰지 않습니다.

## 합성 검증

파서는 원본0/18과 선택 수량·직접 평가값을 독립 보존하고, 누락·양식 오류·음수/소수 수량을 다룹니다. 화면은0수량에서도 단가 기준 비교를 표시하고 증권사 수익률이 있으면 우선하며, 이후 시세가 바뀌어도 두 출처를 혼합하지 않는지 검사합니다. 이전2.2.13에서는0수량 수익률 표시 회귀가 실패했고 수정본에서 통과했습니다.

CSV는 직접 증권사 값과 계산값, 매매/보통 문맥과 시각을 나눠 기록합니다. 수량0이18로 바뀌거나 체결이 생기지 않고 기존 주문 안전 검사가 유지되는지 검사합니다. 모든 검증은 합성 자료이며 실제 Indi 조회·주문을 도구로 실행하지 않았습니다. 새 EXE의 실제 증권사 평가값과 수량 원인은 다음 실행 보고서로 확인해야 합니다.
