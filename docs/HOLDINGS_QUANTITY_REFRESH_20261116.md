# 매수 접수 후 잔고 수량 응답으로 운영이 중단되는 문제

2.2.13은 정상 잔고 응답의 두 수량을 비교하다 전체 운영을 중단한 파서 오류를 수정합니다.

## 확인된 근거

사용자가 제공한 2026-11-16 로그에서09:03:04 매수 주문은 `result=Accepted`와 정상 식별자 분류로 응답했습니다.09:03:05 직후 잔고 조회도 `ErrorState=0`으로 응답했으나, 프로그램이 `SABA609Q1 orderable quantity exceeds trade-basis holdings multi[4/10]` 예외를 발생시켜 중단했습니다. 재연결 후09:05:51,09:06:17에도 같은 예외가 반복됐습니다. 정상 매수 접수 뒤 잔고 응답 처리에서 발생한 중단이며, 이 로그만으로 매수 체결 완료를 단정할 수 없습니다.

사용자가 앞서 내보낸 실제 설치 `SABA609Q1` 정의는3844바이트, SHA256 `e32630bb4232c1166b5a56e9a129c666808fa7c4f8a81492fa8215702eecef67`입니다. 전체 구조를 EOF까지 확인한 필드는 다음과 같습니다.

| 반복출력 | 이름 | 별칭 |
|---|---|---|
| MO4 | 잔고수량 | remq_qty |
| MO9 | 결제일수량 | dcd_qty |
| MO10 | 주문가능수량 | ord_aval_qty |
| MO11 | 미체결수량 | ncntr_qty |
| MO32 | 평가잔고수량 | evlt_base_qty |

공식 Helper와 설치 정의에는 `MO10 <= MO4`라는 보장이 없습니다. MO4를 결제수량으로 재해석하거나 MO10·MO32로 대체할 근거도 없습니다. [신한 잔고 안내](https://file.shinhansec.com/help/goodi_slite/5400.htm)는 조회 화면별 반영 속도에 따라 수량이 다를 수 있음을 설명하지만, 이번 응답의 실제 숫자나 차이가 발생한 세부 원인은 로그에 없습니다.

## 변경된 처리

- MO4,MO10,MO11을 별도로 보존합니다. 대소관계만으로 정상 조회 전체를 실패시키지 않으며 음수·소수·범위 초과 등 잘못된 수량 검사는 유지합니다.
- 수량 차이가 있어도 연결, 계좌 조회, 시세 감시, 후보 분석과 기존 운영 승인을 유지합니다. 기존 직렬 요청 큐와 요청 간격을 사용해10초 뒤부터 다시 조회합니다.
- 보유 원가가 불완전할 가능성이 있으므로 추가 매수와 매수 정정은 최종 준비도 검증에서 보류합니다. 해당 종목 매도도 실제 보유·가능수량 범위를 독립 확인합니다. 다른 종목 매도와 취소는 각자의 기존 검증을 따릅니다.
- 준비도 검증은 외부 DTO의 진단 표시를 신뢰하지 않고 내부에 복사한 원본 수량으로 다시 계산합니다. 새롭고 유효한 잔고 응답에서 관계가 일치하면 이 보류가 해제됩니다. 계좌·당일·신선도·주문·체결 등 다른 조건은 계속 필요합니다.
- 화면과 CSV에 원본 주문가능수량, 수량 대조 결과와 잠정 평가 표시를 추가합니다. 잔고0·주문가능 양수인 행도 표시·시세 등록을 유지하고, 수량 확인 중에는 저장된 추적 최고가를 삭제하지 않습니다.
- 잔고 차이로 보유수량을 합산·보정하거나 체결을 만들어내지 않습니다. 접수 주문번호와 기존 기록을 보존하며 접수·불명 주문을 재전송하지 않습니다.

## 검증과 한계

합성 정상 콜백→파서→실제 폼 경로에 접수 매수 이후 `잔고0/주문가능2` 응답을 주입합니다. 전역 중단이 없고 운영 승인·조회·주문 식별자·최고가·원본 행이 유지되며 주문 재전송이 없음을 검사합니다. 이어 `잔고2/주문가능2` 응답으로 수량 표시와 보류가 해제되는 경로를 검사합니다.

준비도 테스트는 충분한 현금·가능수량과 이미 대사된 매수 체결이 있어도 불일치가 남아 있으면 추가 매수가 차단되는지, 다른 종목 매도는 독립 동작하는지, DTO 변경으로 검사를 우회할 수 없는지를 확인합니다. 보고서는 원본 수량·잠정 상태와 접수 주문번호를 보존하며 가짜 체결을 기록하지 않는지 검사합니다.

모든 검증은 격리된 합성 자료와 가짜 전송을 사용합니다. 실제 Windows Indi 계좌에서 새 EXE의 해당 응답 처리, 수량 차이의 실제 해소와 후속 자동매매 유지는 아직 검증하지 않았습니다.
