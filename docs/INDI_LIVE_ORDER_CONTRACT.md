### 주문 응답

두 XTR 모두 단일 출력6개다.

| SO | 항목 | 처리 규칙 |
| ---: | --- | --- |
| 0 | 주문번호 | 비어 있거나0이면 접수 성공으로 처리하지 않는다. 숫자 문자열을 보존해 주문 식별자로 사용한다. |
| 1 | ORC주문번호 | 일반 주문번호와 별개의 식별자. 상호대체하지 않는다. |
| 2 | 메시지 구분 | Helper는0 가능수량 불표시,1 가능수량 표시, 기본 공백으로 안내한다. |
| 3 | 메시지1 | 신규 성공 시 총주문금액; 실패 시 매수 증거금부족금액 또는 매도 유가증권부족수량. |
| 4 | 메시지2 | 신규 성공 시 가계산수수료; 실패 시 주문가능수량. |
| 5 | 메시지3 | 신규 매도 성공 시 가계산제세금; 매수 실패 시 주문가능금액. |

**Helper는 주문번호0의 오류에서도 `ErrorState=0`이 들어온다고 명시한다.** 따라서 `ReceiveData` 수신이나 오류상태0만으로 주문 성공을 표시하면 안 된다. 양수 주문번호는 접수 결과이며 체결 증거가 아니다. 메시지 값의 의미는 성공·실패·매수·매도에 따라 달라지므로 임의로 손익이나 잔고에 반영하지 않는다. 공급자 메시지는 계좌·암호가 포함될 수 있어 로그에 원문을 남기지 않는다.

| 21 | 확인구분 | `0` 정상, `1` 거부, `2` 접속실패, `3` 거래소거부. 정상은 전량 체결과 다르다. |
| 22 | 체결시간 | 개별 체결 식별자가 아니다. |
| 24 | 체결수량 | 건별구분0이면 주문별 합산값. 이벤트 증분으로 더하지 않는다. |
| 25 | 체결단가 | 건별구분0이면 평균단가. |
| 26 | 미체결수량 | 누적 체결·취소·정정 수량과 대조한다. |
| 28 | 확인수량 | 현재 상태 확인용. |
| 29 | 신용구분 | `00` 일반 등. 일반 현금 경로에서 다른 신용 코드를 수락하지 않는다. |
| 31 | 상태명 | 의뢰·접수·확인·거부. 이름만으로 체결/취소확정을 추정하지 않는다. |
| 32 | 현재가 | 주문 체결가와 구분한다. |
| 33 | 주문조건 | `0` 일반, `3` IOC, `4` FOK. |
| 35 | 자동취소수량 | 잔여 수량 대사에 반영할 별도 사실. |
| 36 | 운용사지시번호 | 사용자 주문 추적 ID와 동등하다고 가정하지 않는다. |
| 37 | 공매도구분코드 | 일반 현물 경로에서 공매도를 허용하는 근거로 사용하지 않는다. |
| 38 | 매매단위수량 | 주문 단위 검증 자료. |

이 조회에는 Helper상 체결번호가 없다. 체결시각·수량·단가 조합을 고유 체결번호라고 가정하지 않는다. XTR은 반복 출력39 사이버ID,40 신용상환조건코드도 정의한다. 페이지/연속조회·완결 표시의 규약은 확보한 자료에서 확인되지 않았다. 잘린 응답이나 확인되지 않은 행 제한을 전체 주문 대사가 끝났다는 증거로 사용하면 안 된다.

## 현물 실시간 이벤트 AA·AD

Helper는 `AA`를 **현물 실시간 주문체결**, `AD`를 **실시간 잔고**로 정의한다. `AB`는 선물옵션 실시간 주문체결이고 `AE`는 선물/옵션 잔고다. 따라서 현물 앱에서 AB/AE까지 현물 이벤트로 파싱하면 안 된다. 이 배포물에는 별도 AA/AD 조회 파일이 없어 이벤트 정의는 Helper 안내가 근거다.

## 실주문을 열기 전에 남은 검증

필드 빌더·파서·가짜 전송·재시작 저널 테스트는 실제 서버 인증이 아니다. 사용자 승인과 코드 존재만으로 다음 항목이 검증됐다고 표시하지 않는다.

1. 사용 중인 설치 버전의 신규/정정/취소 필드13·17~35, 프로그램매매 코드, 가격/수량 및 시장/SOR 규칙을 현재 공식 명세와 대조한다.
2. 현금100% 주문가능금액/수량의 의미, 수수료·미체결 예약금·외부 주문 반영 시점과 조회 완결성을 검증한다.
3. 접수 성공·주문번호0 실패·거래소 거부·부분체결·정정·취소 요청과 확정을 서로 다른 상태로 검증한다.
4. AA 중복/역순/누락, AD 잔고, 조회 스냅샷과 외부 수동 거래의 대사가 완료돼야 한다.
5. 접수 직후 단절·타임아웃·응답 유실·재시작은 불명 주문으로 남기고 자동 재전송하지 않는다. 이 상태에서 예약금/수량을 풀거나 새 주문을 허용하지 않는다.
6. 최신 휴장일·거래 세션·가격 단위·주문 유형과 실제 시세 날짜의 검증은 별도다. 오래된 Helper의 KRX/ECN 코드만으로2026년 시장 라우팅을 확정하지 않는다.

새 주문·정정·취소 구현은 검증 전 잠금을 유지한다. 이 문서를 작성하면서 실제 돈을 쓰는 주문은 한 건도 전송하지 않았다.
