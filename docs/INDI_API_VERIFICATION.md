# Indi 인터페이스 확인 기록

확인일: 2026-11-12 UTC. 이 기록은 인터넷 자료 조사와 소스 분석 결과이며, 실제 Windows Indi 서버에서 실행한 검증 결과가 아니다.

## 확인된 공식 근거

| 자료 | 확인 내용 | 한계 |
| --- | --- | --- |
| [신한투자증권 Indi 서비스](https://www.shinhansec.com/siw/customer-center/channel/channel_homeTrading-indi/contents.do) | ActiveX 인터페이스와 사용자 인터페이스 문서/예제 제공을 안내한다. | 현재 국내 현물 주문 TR의 전체 입출력 명세는 페이지 본문에서 확인되지 않았다. |

공식 페이지의 검색 색인 본문은 확인했지만, 이 작업 환경의 직접 HTML 요청은 HTTP 503을 반환했고 웹 페이지 열기는 메뉴 외 본문을 표시하지 못했다. 이전 공식 도메인 `www.shinhaninvest.com`도 유효한 상세 문서를 제공하지 못했다. 그러므로 다운로드 파일을 확보하거나 최신 공식 필드 명세를 대조했다고 보고하지 않는다.

## 보조 자료와 현재 코드의 위치

[WikiDocs 책 소개](https://wikidocs.net/book/2167)는 신한투자증권 공식 페이지가 아닌 개인 작업물이라고 명시한다. 따라서 아래 자료는 기존 구현을 이해하는 데 사용했으며, 최신 공식 사양 인증의 근거가 아니다.

| 기능 | 기존 코드의 TR / 필드 사용 | 보조 자료 | 현재 판정 |
| --- | --- | --- | --- |
| 전체 종목 | `stock_mst`; 코드 1, 시장 2, 이름 3, 위험/상품 분류 6/7/8/14 | [종목 조회](https://wikidocs.net/22664) | 모의 파서로 검증 가능. 실제 종목 수, 필터 의미, 누락 여부를 Windows에서 대조해야 한다. |
| 일봉 | `TR_SCHART`; 입력 코드/주기/간격/시작/종료/봉수, 출력 날짜와 OHLCV | [일봉 조회](https://wikidocs.net/78514) | 정렬/유효성/숫자 해석은 자동 검증 대상. 실제 봉 필드와 미완성 당일 봉은 서버 대조가 필요하다. |
| 현재가 | `SC`; 코드 1, 체결시각 2, 가격 3, 장구분 17 | [실시간 시세](https://wikidocs.net/book/2167) | 실제 종목 일치, 체결시각, 장구분을 HTS와 대조해야 한다. 시각만으로 당일 데이터임을 보장할 수 없다. |
| 잔고 | `SABA200QB`; 계좌/상품구분/비밀번호 입력, 종목별 수량/미체결/단가 | [잔고 조회](https://wikidocs.net/22715) | 조회 전용. 잔고 수량의 변화는 특정 주문의 체결 증거가 아니며, 잔고/예수금은 주문가능금액이 아니다. |
| 국내 현물 주문 | 이전 Python의 `SABA101U1` | [2020년 매수/매도 예제](https://wikidocs.net/21907), [불완전한 TR 소개](https://wikidocs.net/84559) | 현재 공식 입력/응답 사양 미확인. 새 주문 전송 어댑터를 임의 구현하지 않으며 기존 Python 전송도 차단한다. |

`SABA101U1`의 이름과 오래된 시장가 예제만으로 필수 입력값, 기본값, 거래소/대체거래소 선택, 정정/취소, 오류코드 또는 현금100% 주문 제한을 확정할 수 없다. 소스에 필드 번호를 추가해 놓는 것을 공식 API 구현 완료로 취급하지 않는다.

## 실주문이 계속 잠기는 이유

사용자의 승인만으로 잠금을 풀 수 있는 설정은 제공하지 않는다. 이 변경의 모의 주문·체결·미체결·예약금·중복방지·재시작 복구 테스트는 로컬 엔진의 일관성을 검증한다. 증권사 주문 어댑터나 실제 체결 수신 검증을 대신하지 않는다. 이 버전에서는 실제 주문을 전송하지 않는다.

아래 공식 자료와 Windows 검증이 확보되어야 후속 변경을 검토할 수 있다.

1. 사용 중인 `IndiSetup.exe`/OCX의 버전, 배포 출처와 해시, 설치된 typelib의 이벤트 IID/DISPID/인자형을 기록한다. `ReceiveData` 및 시스템/실시간 이벤트를 연결한 뒤 조회 응답 수신과 종료/재연결을 확인한다.
2. Indi Helper 또는 공식 인터페이스 문서에서 국내 현물 신규·정정·취소 TR의 전체 입력/출력 정의, 주문번호와 오류코드 의미, 현금/신용/대출 구분, 시장과 주문유형별 규칙을 확보한다. 계좌번호/암호/인증서는 소스·PR·진단 로그에 넣지 않는다.
3. 현금100% 주문가능금액 TR과 정확한 출력 필드, 조회 기준시각, 수수료/세금/기존 미체결 예약금 포함 여부를 확인한다. UI 투자원금, 예수금, 가상현금, 수동 HTS 확인값으로 대체하지 않는다.
4. 최초 주문/체결/미체결/잔고 스냅샷과 `AA`/`AB`/`AD`/`AE` 이벤트를 주문번호·체결번호로 결합한다. 부분체결, 중복·역순·누락 이벤트, 거절, 취소 대기와 확정, 정정된 원주문 관계를 검증한다.
5. 주문 접수 직후 연결 단절, 응답 유실, 프로그램 재시작에서 불명 주문을 자동 재전송하지 않는지 확인한다. 서버 스냅샷/미체결/체결내역 대사가 끝나기 전 발주를 막는다. 외부 수동거래도 별도 식별한다.
6. 공식 모의 서버 제공 여부와 지원 주문유형을 신한에 확인한 다음 그 환경에서 검증한다. 실제 돈을 쓰는 검증은 별도의 사용자 승인 이후에만 진행한다.

Windows 확인 시에는 최소한 시각/타임존, EXE 커밋, OCX 버전, TR명, 요청번호, 응답 행수, 익명화한 기대값/실제값과 판정을 기록한다. 단순 `RequestData` 반환, 주문번호 수신 또는 잔고 증감만으로 체결 성공이라고 보고하지 않는다.

## 기존 Python 경로 검토

기존 `app.py`는 GUI 실행과 `place()`에서 LIVE 주문을 막지만, `indi_client.py`에는 `order()` 및 `request('order', ...)`가 직접 `SABA101U1`을 호출할 수 있는 경로가 있었다. UI 차단만으로는 어댑터를 직접 호출하는 코드를 막지 못한다. Python API 수준에서도 주문 요청을 거절하고 CI에서 직접 호출이 COM에 도달하지 않음을 검증해야 한다. C# Windows 빌드 산출물과 이전 Python 빌드 스크립트도 분명히 구별해야 한다.
