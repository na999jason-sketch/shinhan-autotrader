# 현재 평가잔고수량을 사용하는 수량 선택 수정

2.2.15는 당일 매수를0주로 인식한 원인을 수정합니다. 현재 설치의 정상609응답이 제공하는 평가잔고수량을 직접 선택하고, 원본 잔고수량과 분리합니다.

## 실제 응답으로 확인된 관계

사용자가 제공한11월16일09:51 KST 보고서에서 매매기준 SI3=1과 보통잔고 SI3=5는 다음 값을 각각 반환했습니다.

| 항목 | 값 |
|---|---:|
| 원본 잔고수량 MO4 |0|
| 전일·당일 매도 MO5/6, 전일 매수 MO7 |0|
| 당일 매수 MO8 |18|
| 결제일수량 MO9 |18|
| 주문가능수량 MO10 |18|
| 미체결수량 MO11 |0|
| 평균단가 MO12 |8,160|
| 해당 콜백 현재가 MO13 |7,870|
| 증권사 평가금액 MO18 |141,660|
| 증권사 미실현손익 MO19 |−5,220|
| 증권사 손익률 MO20 |−3.55%|
| 평가잔고수량 MO32 |18|

계좌 SO15 매입금액146,880원과 SO18 평가금액141,660원도 각각 `18×8,160`, `18×7,870`과 일치합니다. 당일 주문과 프로그램 기록은 매수18주 전량체결을 확인합니다. 원본 파일과 계좌·주문 식별자는 저장소에 포함하지 않습니다.

기존 코드는 MO4 하나를 현재 보유수량으로 사용했습니다. 따라서0주로 계산하고18주 주문가능수량과 충돌한다고 판단했습니다. 새 자료는 단순 반영 지연으로 기다리는 대신, 명시적으로 제공된 평가잔고수량을 검증해 현재 수량으로 사용할 근거를 제공합니다. MO4를 결제수량 등 다른 의미로 임의 재명명하지 않습니다. MO9·당일 매수·체결수량의 일치는 이번 자료의 보강 증거이며 모든 종목에 강제하는 계산식이 아닙니다.

## 조회 정의와 요청별 연결

`IndiHoldingsSchema`는 설치된609정의를 읽어0x0208, 입력8·단일37·반복39, 모든 필드의 이름·별칭·자료형·폭·FID, SC/WC 연결 메타데이터와 EOF를 검증합니다. 실제3844바이트 파일은 SHA256 `e32630bb4232c1166b5a56e9a129c666808fa7c4f8a81492fa8215702eecef67`로 정상 인식했습니다. 이는 정적 파일 확인이며 실제 계좌 조회가 아닙니다.

코디네이터는 모든 입력 설정 성공과 쿼리명 확인 후 불변 조회 정의를 현재 요청에 연결합니다. 정상 상태와 요청번호가 일치하는 콜백에만 전달하며, 재시도마다 새로 확인합니다. 설정 실패·다른 쿼리/요청번호·오류 응답·재진입·중단된 요청이 새 수량 근거를 만들지 않습니다.

## 현재 수량의 조건

확장 정의와 매매기준 또는 보통잔고 요청 연결이 확인된 경우 다음 조건을 사용합니다.

- 직접 반환된 MO32가0이상 정수이고 지원하는 수량 범위 안에 있어야 합니다.
- 양수 수량은 같은 콜백의 원본 MO13 가격이 양수이고, `MO32×원본 MO13=MO18`이 정확히 맞아야 합니다. 곱셈 범위 초과도 거부합니다.
- 0주에서는 MO18과 주문가능수량이0이어야 하며, 원래 MO4가 양수여도18주로 되살리지 않습니다.
- 주문가능수량은 검증된 현재 수량을 넘지 않아야 합니다. 미체결 MO11을 더하거나 빼지 않습니다.
- 원본 MO4, 선택 수량, 평단, 원본 가격·평가금액과 요청 문맥은 별도 내부 증거와 재대조합니다. 이후 SC 표시 가격 변경은 원본 콜백 가격과 구분합니다.

확장 정의인데 현재 수량 검증이 실패하면 원본 행을 유지하면서 미검증으로 표시하고 추가 매수·해당 종목 매도를 보류합니다. 구형·미인식 정의는 기존 MO4 경로를 유지합니다. 수량을 금액으로 나누거나 주문가능수량·확인 체결수량으로 대체하지 않습니다.

## 주문·평가·보고서 연결

검증된 현재 수량은 보유 원가와 운용한도, 최대 보유종목 수, 손절 판정, 매도 수량에 사용됩니다. 보고서 사례의 보유 원가는146,880원입니다. 미체결 매수 예약금과 기존 주문별 체결 대사를 유지합니다. 부분 매수10주·남은8주를18주 보유로 합산하지 않으며,18주 보유·매도 대기10주·가능8주에서는 가능한 수량을 초과해 매도하지 않습니다.

매매기준과 보통잔고 모두 같은 검증을 적용하지만 요청 기준은 바꾸지 않습니다. 보통잔고는 `BasisVerified=true`로 승격하지 않습니다. 현물 대조 시 인식된 확장 프로필의 미검증 수량은 원본 숫자가 우연히 같아도 거부합니다. 매수에 불필요한 새 보통잔고 조회 조건을 추가하지 않습니다. 신용수량도 선택된 현재 수량으로 계산하고 현물·융자·가능수량 검사를 유지합니다.

CSV의 MO4는 언제나 원본 값입니다. 현재 수량·출처·검증 결과·고정 진단·조회 정의 해시는 별도 칸에 기록합니다. 화면도 평가잔고18주와 원본0주를 구분합니다. 기존 접수·체결 기록을 지우거나 원주문을 재전송하지 않습니다.

## 검증과 한계

합성 정상 콜백을 실제 폼 처리 경로에 넣어18주·매입146,880원·평가141,660원 표시와 손절 판정, 보통잔고 대조, 기존 체결 보존과 추가 전송0회를 확인합니다. 준비도는18주 매도 가능·초과 차단, 보유 원가를 반영한 새 매수 한도, 부분체결·미체결 예약금·신용·취소·전량 매도 후0주와 공개 DTO 변경을 검증합니다.

실제 설치 파일 인식과 사용자 원본 응답 관계는 확인했지만, **새 EXE의 실제 Windows Indi 현재 수량 반영·자동 매도·후속 매수는 아직 검증하지 않았습니다.** 도구로 실제 계좌 조회나 금전 주문을 실행하지 않았습니다. 합성 검증과 Windows 빌드는 실제 거래나 수익 검증을 대신하지 않습니다.
