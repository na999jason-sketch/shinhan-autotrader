# 실제 매도 접수 확인과 후속 실시간 장애 — 2026-11-13 KST

사용자가 제공한2.2.6 실행 화면·진단과 HTS/MTS 확인을 근거로 한다. 계좌번호·주문번호·원본 로그와 실제 보유 명세는 이 문서에 복사하지 않는다. 이 작업의 도구로 실제 계좌 조회나 금융 주문을 실행하지 않았다.

## 확인된 범위

사용자는 국내주식 매도 주문1건이 실제 증권사 앱에 접수됐다고 확인했다. 같은 요청의 앱 응답은 Modern·Accepted였고, SOR 슬롯0은0, KRX 슬롯1은 양수, NXT 슬롯2는0, ORC 슬롯3은 공란이었다. 통신 상태와 오류 상태는 모두0으로 기록됐다. 이는 **실제 매도 접수1건과 대응 KRX 식별자의 확인**이며 체결 완료의 증거는 아니다. 통신 상태0만으로 계좌·시세·후속 이벤트 전체가 정상이라고 판단하지 않는다.

해당 진단에는 실시간 시스템 알림을 설명하는 줄이 없었고, 기존 실패 경로가 상세 원인을 버렸다. 따라서 AA·AD 중 어느 이벤트·필드가 실패했는지, 시스템 알림이 있었는지, 실제 공급자 값이 어떤 형태였는지는 확정하지 않는다. 잔고 행수 감소를 특정 주문의 전량 체결로 바꾸거나 누적 수량을 개별 체결로 만들어서는 안 된다.

## 2.2.7 변경 범위

- 실시간 파싱 실패를 이벤트 종류·필드 번호·고정 실패 분류로 남긴다. 공급자 원문·계좌·암호는 복사하지 않는다. 원인 확인을 위한 진단이며 현재 장애의 근본 원인을 이미 찾았다는 의미가 아니다.
- 양수 증권사 주문번호와 정상 접수 증거가 함께 있는 주문은 `접수확인·체결대사필요`로 표시한다. 후보 식별자만 있거나 접수 증거가 없는 불명 주문을 이 상태로 승격하지 않는다.
- 주문 표의 선택과 새로 도착한 응답 표시를 유지해, 과거 거절 행과 최신 접수 응답을 혼동하지 않도록 한다.
- 주문 채널 준비 과정에서 메시지 처리가 재진입할 수 있으므로, 중단·폐기·계좌 변경·운영 승인과 채널 동일성을 다시 검사한다.

실시간 장애가 나면 추가 주문을 중단하고 이미 접수된 주문의 기록을 보존한다. 금액·매도가능수량·미체결·개별 체결 식별자·시세와 계좌 자료의 신선도 검증은 유지하며, 대사되지 않은 주문을 자동 재전송하지 않는다. 운영 중단이 증권사에 접수된 주문을 자동 취소한 것으로 표시하지 않는다.

## 남은 실제 검증

새 진단으로 이벤트 종류와 실패 필드를 확인하고 현재 설치 정의·실제 수신 형식을 대조해야 한다. 이후 개별 체결번호·수량·가격, 주문별 누적 체결·미체결, 후속 잔고가 일치하는지 확인해야 한다. 실제 매수·정정·취소·부분체결 처리·재시작 복구와 무인운영도 남아 있다. 한 건의 접수나 합성 테스트 성공을 전체 서버 동작·체결 완료·수익성 검증으로 확대하지 않는다.
