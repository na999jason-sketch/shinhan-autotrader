# 국내주식 조회 필드 대조 기록

확인일: 2026-11-12. 공식 배포 설치 파일을 실행하지 않고 추출한 조회 리소스와 Helper 안내 자료를 대조했다. 이 기록은 자료의 필드 정의를 확인한 결과이며, 사용자 PC의 설치 파일이 같은 버전이라는 증거나 실제 서버 반환값 대조 결과는 아니다.

## 자료와 해시

- 공식 배포 주소: `http://file.shinhaninvest.com/filedoc/download/IndiSetup.exe`
- 설치 파일: 28,757,720 bytes, SHA256 `5f18d7ca4ddc1f44835cf64ffa214844b8525cf0e37323351c99c661fadc318f`
- 설치 파일 서명 확인 범위와 OCX 분석은 [통신 분석 기록](INDI_IPC_EVIDENCE.md)을 참조한다.
- 아래 리소스의 필드명과 인덱스만 대조했다. 신한 바이너리와 조회 정의 파일은 저장소에 재배포하지 않는다.

| 추출 파일 | 크기(bytes) | SHA256 |
| --- | ---: | --- |
| `config/helpertrinfo.dat` | 178,764 | `2502350aed41217edfd2aaf1b754de7c036046ed392dda028ca47e623f5af05b` |
| `qry/tr_schart.xmf` | 903 | `a5e227d598ca4aeb5dcfacba669136565501536dc3c227db8f6f9becc6237f78` |
| `qry/saba200qb.xtr` | 572 | `8b8477598f140906e0d4b202b9e165b23d54ab3a02c4fd7e7227398650b19c93` |

이하 인덱스는 모두 0부터 시작한다. SI는 단일 입력, SO는 단일 출력, MO는 반복 출력이다.

## SC 현물현재가

Helper 안내의 `SC` 구역은 입력과 출력을 다음과 같이 정의한다. 추출한 `qry` 디렉터리에는 별도 SC 조회 파일이 없다.

| 구분 | 인덱스 | 필드 |
| --- | ---: | --- |
| SI | 0 | 단축코드 |
| SO | 0 | 표준코드 |
| SO | 1 | 단축코드 |
| SO | 2 | 체결시간 |
| SO | 3 | 현재가 |
| SO | 17 | 장구분 |

장구분 안내는 1 정규장, 2 장개시 전 시간외, 3 장종료 후 시간외종가, 4 장종료 후 시간외단일가, 7 일반 BUY-IN, 8 당일 BUY-IN이다.

기존 C#의 코드1/시각2/가격3 인덱스는 이 안내와 일치한다. 사용자 1.4.1 로그에서는 SC 요청번호7의 `ReceiveData`가 오류상태0으로 도착한 뒤 파서가 실패했다. 이 로그만으로 필드 번호가 틀렸다고 단정할 수 없다. 실제 반환 VARIANT 형식, 공백·시간 표현 및 필요한 값의 유무는 응답 시점에서 추가 확인해야 한다. 이 안내의 필드명만으로 체결시간의 정확한 문자열 표현이나 당일 시세 여부를 보증하지 않는다.

## TR_SCHART 일봉

조회 리소스와 Helper 안내에서 현재 코드가 사용하는 다음 필드 순서는 일치한다.

| 구분 | 인덱스 | 필드 / 현재 입력 |
| --- | ---: | --- |
| SI | 0 | 단축코드 |
| SI | 1 | 그래프 종류 / `D` 일봉 |
| SI | 2 | 시간간격 / `1` |
| SI | 3 | 시작일 / `00000000` |
| SI | 4 | 종료일 / `99999999` |
| SI | 5 | 조회 개수 / 전략에 필요한 봉 수 |
| MO | 0 | 일자 |
| MO | 1 | 시간 |
| MO | 2 | 시가 |
| MO | 3 | 고가 |
| MO | 4 | 저가 |
| MO | 5 | 현재가(해당 봉 가격) |
| MO | 9 | 단위거래량 |

Helper 안내는 일/주/월 간격을1로 정의하고 조회 개수 범위를1~9999로 안내한다. 시작/종료일 기본 예시는 각각 `00000000`/`99999999`이며, 설명에서는 이 특수값을 분 데이터 요청에 명시한다. 일봉 요청에서 현재 특수값 조합을 서버가 수락하는지는 별도 실서버 확인이 필요하다. 필드 길이·기본 예시를 확인한 것을 모든 날짜 조합의 유효성 검증으로 취급하지 않는다.

날짜 중복, 잘못된 수치, OHLC 관계와 필요한 봉 수는 앱에서 검증하지만 실제 조회값, 정렬, 거래량 단위 및 수정주가 처리의 HTS 일치는 아직 확인하지 않았다.

## SABA200QB 잔고 및 주문체결 조회

두 자료에서 일치하는 입력은0 계좌번호,1 상품구분,2 비밀번호다. Helper 안내는 계좌번호11자리, 상품구분 `01`, 비밀번호4자리를 설명한다. 실제 자격증명은 이 문서나 로그에 기록하지 않는다.

출력0 종목코드,1 종목명,2 결제일 잔고수량,5 현재가,6 평균단가,7 신용잔고수량,8 코스피대용지정수량은 두 자료가 일치한다. 결제일 잔고수량을 주문가능수량이나 특정 주문의 체결 증거로 해석하지 않는다.

**매수/매도 미체결 수량의 3/4번 이름은 같은 설치 파일의 자료끼리 충돌한다.**

| 자료 | MO3 | MO4 |
| --- | --- | --- |
| `helpertrinfo.dat`의 SABA200QB 안내 | 매도 미체결 수량 | 매수 미체결 수량 |
| `saba200qb.xtr`의 실제 레이블 | 매수 미체결 수량 | 매도 미체결 수량 |

따라서 리소스 하나만 보고 매수/매도 이름을 확정하거나 실제 미체결 관리가 검증됐다고 표시할 수 없다. 현재 설치된 공식 인터페이스 정의 및 서로 다른 매수/매도 미체결 수량이 있는 상태의 HTS 대조로 확인해야 한다. 실제 주문을 보내서 이 차이를 시험하지 않았다.

Helper는 잔고가 없고 매수 미체결만 있는 종목의 평균단가가0일 수 있다고 설명한다. 빈 잔고 또는0 평균단가 자체를 공급자 오류로 해석하지 않되, 콜백이 오류 상태이면 빈 잔고 성공으로 처리하지 않는다. 실제 현금 주문가능금액·체결/미체결 대사와 실주문은 이 조회 자료만으로 구현 완료를 주장하지 않는다.

## TR_1110_11 현재가 조회

공식 `qry/tr_1110_11.xmf`는 1,524 bytes이며 SHA256은 `d3c692d8503095c9f97227952432a38c150b960d5a9335aa83a53053359f346e`다. 리소스의 이름은 `현재가 종합 화면용 상단 왼쪽`이고 Helper 안내에도 같은 조회가 있다.

| 구분 | 인덱스 | 필드 / 정의 |
| --- | ---: | --- |
| SI | 0 | 단축코드 / `SHRT_CODE`, 문자열 6자리 |
| SO | 0 | 전일종가 / `HST_TRDPRC_1` |
| SO | 12 | 상한가 |
| SO | 13 | 하한가 |
| SO | 24 | 현재가 / `TRDPRC_1`, 문자열 9자리 |

입력 레코드는 단축코드 하나이며 저장된 기본값은 비어 있다. Helper의 `055550`은 입력 예시다. 앱은 사용자가 고른 유효한 6자리 단축코드를 전달한다. 출력 레코드는 31개 필드이며, 현재가24의 위치는 리소스와 Helper가 일치한다. 리소스에는 SC를 단축코드로 연결해 현재가를 갱신하는 정의도 있지만, 조회 출력 자체에는 종목코드 재반환, 체결시각 또는 시세 날짜가 없다.

따라서 수동 `현재가 조회`는 요청번호와 요청 종목을 대조한 뒤 이 조회의 가격을 표시할 수 있다. 시각을 현재 PC 시간으로 만들어 넣거나 이 응답을 최신 체결가로 간주하지 않는다. 시각 미확인 현재가는 자동 매수·매도의 근거로 사용하지 않으며, 자동 처리에는 별도 SC 응답과 시각 검증이 필요하다.

Helper 시작행의 숫자는 `TR_1110_11=0,1,0`, `SC=0,1,1`, `AA=0,0,1`이다. 이 차이만으로 SC가 조회 요청을 지원하지 않는다고 단정하지 않는다. 사용자 SC 실패의 실제 필드 값이 없는 상태에서 새 조회 경로의 추가를 SC 장애 원인의 확정으로 표시하지 않는다. 수정된 수동 조회의 실제 반환 가격과 HTS 대조는 아직 확인하지 않았다.
