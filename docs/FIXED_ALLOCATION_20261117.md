# 종목당 배분 기준 수정 — 2.2.18

이전 자동 매수 수량 계산은 남은 현금·잔여 운용한도·종목 가능금액 중 최솟값에 배분 비율을 곱했다. 따라서20% 설정에서 앞선 매수가 진행될수록 다음 주문의 목표금액도 줄었고, 남은 금액으로1주 이상을 살 수 있어도 다시20%를 적용해0주로 계산될 수 있었다.

수정한 자동 매수 계산은 다음과 같다.

```text
종목당 목표금액 = 설정된 전체 운용한도 × 저장된 배분 비율
잔여 운용한도 = max(0, 전체 운용한도 − 현재 보유 원가 − 미체결 매수 예약금)
허용금액 = min(목표금액, 현금100% 주문가능금액, 잔여 운용한도, 종목 가능금액)
계산수량 = floor(허용금액 ÷ (지정가 × (1 + 설정 비용 여유율)))
주문수량 = min(계산수량, 증권사 종목 가능수량, 기존 100,000주 상한)
```

운용한도100만원·배분20%에서 목표금액은20만원이다. 현재 가용금액이100만원·80만원·20만원으로 줄어도 목표금액은 같고, 가용금액이5만원이면 허용금액이5만원으로 제한된다. 이5만원에20%를 다시 곱하지 않는다. 주당1만원·비용 여유율0.3%이면 충분한 가용액에서19주,5만원 상한에서4주다. 정수 주식수와 비용 여유분 때문에 실제 주문 원금이 목표금액과 정확히 같지는 않다.

`Program.SubmitPending`은 실제 기존 보유 원가와 저널의 예약금을 차감한 잔여 운용한도, 현금·가능금액을 구한 뒤 별도 전체 운용한도를 수량 계산 함수에 전달한다. 구버전3/4인자 계산 함수는 같은 금액을 총예산·가용액으로 전달하는 호환 경로로 남기고, 실제 자동 매수는 총예산과 현재 상한을 구분한5인자 경로를 사용한다.

최종 준비도와 주문 전송의 현금·운용한도·가능수량 검사는 그대로다. 잔여 운용한도가0이거나 현금/가능금액이0이면 주문하지 않는다. 미체결 매수는 예약금으로 남고, 취소 접수만으로 해제되지 않는다. 실제 취소 확인 후에만 확인된 잔량의 예약금이 해제된다. 최대 보유종목 수는 별도 제한으로 유지하며 자동으로 늘리지 않는다. 기존 보유 종목을 목표금액까지 자동 추가 매수하는 기능도 넣지 않는다.

설정 필드명`AllocationFraction`·저장값·기본20%는 유지하고 화면 이름을 `종목당 전체 운용한도 배분 (%)`로 바꿨다. 손절·익절·추적손절,2%·60초 진입 조건,120초 미체결 취소 정책, 계좌·주문·체결·조회 정의는 변경하지 않는다.

전용 계산 검사47개는 고정 목표·가용액 상한·경계·비용·수량 내림·0/음수·기존 수량 상한을 확인한다. 실제 폼 회귀검사21개는 `SubmitPending`을 통과시켜 초기·보유 원가 증가 후 동일 수량, 각 금액 상한·가능수량·예약금·취소 접수/확인에 따른 수량을 대조한다. 가짜 시세·계좌·전송만 사용했으며 실제 금융 API나 계좌 주문은 호출하지 않았다. 실제 계좌의 새 수량 계산 경로와 투자 수익성은 아직 검증하지 않았다.
