따라서 현재 파서의 주요 필드 인덱스가 밀렸다는 가설은 배제한다. 이 XTR에는 확인구분의0/1 의미가 들어 있지 않으며, 내부명만으로1을 정상으로 해석하지 않는다. 비어 있는 직렬화 설명 문자열을 실제 서버 기본값이나 정상 상태의 근거로 취급하지 않는다. Helper의`1=거부` 설명도 그대로여서 실제 수량·확인코드 충돌은 아직 미해결이다.

## 주문 대기 중에도 계속하는 분석

기존 `EvaluateHoldingSell`은 실제 주문 운영 세션이 해제되면 `장중 감시 대기`를 반환했다. 미확정 주문 때문에 주문 승인을 해제한 뒤에도 정상 시세와 현물 보유를 받아 놓고 손절·익절 판단을 표시하지 못했다. 계좌 조회·주문 사전검증의 조기 반환과 잔고 갱신 시 판정 초기화도 표시 갱신을 밀리게 했다.2.2.9에서 추가한 자동 재검증 대기 문자열은 같은 매도판정 열을 덮어썼다.

2.2.10에서는 다음 동작을 분리한다.

- 계좌 조회·감시에 연결하면 공개 종목 분석을 자동으로 준비한다. 미확정 주문으로 운영 시작이 보류돼도 남은 분석과 후보의 실제 SC 조건 확인을 계속한다.
- 대사 대기로 전환할 때 이미 요청한 일봉 조회를 취소하지 않는다. 대기열에서 꺼낸 종목의 응답과 분석 진행률을 보존한다. 사용자의 운영 중단·종료는 요청을 계속 취소한다.
- 보유의 손절·익절·추적손절은 장중의 검증된 최신 SC와 확인된 실제 보유·평균단가로 계산한다. 조회 Busy·사전검증·계좌 조회 대기보다 먼저 복사된 SC 자료로 판정을 갱신한다.
- `실계좌 잔고·손익`의 `매도판정`에는 전략 판단을, 별도 `매도 주문상태`에는 대사 대기·주문 검증·자동 거절 재검증 등의 전송 상태를 표시한다. 예를 들어 손절 조건을 만족해도 다른 주문 대사 대기로 전송하지 못한다는 사실을 함께 볼 수 있다.
- 미확정 주문이 있거나 실주문 시작 승인이 없으면 새 주문을 만들거나 전송하지 않는다. 분석과 판정이 계속된다는 사실이 자동 주문 재개를 뜻하지 않는다.
- 보유 판정의 조회 근거도 같은 한국 거래일·UTC 요청/수신 순서·120초 이내 여부를 검사한다. 실제 주문 직전에는 기존의 더 엄격한5초 재조회 검사를 유지한다.

SC의 연속 수신·거래시각·신선도, 현물 출처·보유수량·평균단가 검사는 유지한다. 수동 현재가 조회나 PC 시각으로 거래 가능한 SC를 만들지 않는다. 일반 거절 자동 재검증은 기존의 명시적 미접수 근거·대기시간·횟수한도·새 계좌 조회를 계속 요구한다. 사용자가 거절 행을 선택해 재시도할 필요는 없으며, `Unknown` 주문은 그 자동 재시도 대상이 아니다.

## 공란 복구와 이번 충돌의 차이

확인구분이 공란인 응답은 정상코드`0`으로 바꾸지 않고 `Unavailable`로 보존한다. 기존 정상 접수 KRX 원주문과 같은 계좌·당일·주문번호·종목·방향·현금 상품·수량·지정가를 대조하고, 새 요청·정상 콜백·수신5초 이내·전량체결·미체결/취소0·지정가 범위의 평균가·기존 체결 금액 일치를 모두 확인한 경우에만 별도의 `IndependentFullFillWithoutConfirmation` 체크포인트를 저장한다. 거부코드·거부명·거부 상태명 등 상충 증거가 있으면 이 경로도 차단한다.

이 공란 경로는 실제 개별 체결번호를 만들어 내거나 확인구분을 정상으로 정규화하지 않는다. 기존 정상코드 체크포인트와 구분해 저장·재시작·후속 조회에서도 근거를 검사한다. **이번 실제 응답은 공란이 아닌`1`이므로 이 경로로 복구되지 않는다.**

## 추가 진단 자료

| 열 | 기록 범위 |
| --- | --- |
| 거부코드 형태·거부코드명 형태 | `Blank` / `Zero` / `Present` |
| 상태명 분류 | 알려진 `의뢰`·`접수`·`확인`·`거부`, 그 외 `Blank` / `Other` |

임의 공급자 메시지와 계좌 자격정보는 이 추가 열에 복사하지 않는다. 실제 설치의231 정의는 확보·검증됐고, 최신 조회 후 CSV가 있어야 이번`1` 응답을 더 조사할 수 있다. 파일 수집은 진단을 위한 것이며 매도 재전송이나 수동 거절 재시도를 요구하는 절차가 아니다.
