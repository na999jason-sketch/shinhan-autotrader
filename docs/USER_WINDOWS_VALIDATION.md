# Windows 실계좌 운영 확인

대상: Shinhan Native Trader2.0, .NET Framework4.8 x86. 이 안내는 실제 Windows에서 확인할 항목이며, 아래 절차를 작성했다는 사실로 검증 완료를 표시하지 않는다. **현재 배포물의 실주문 게이트는 잠금 상태다. 주문 코드는 포함돼 있지만 신규·정정·취소를 전송하지 않는다.**

## 출근 전에 준비

1. [PR #1](https://github.com/na999jason-sketch/shinhan-autotrader/pull/1)의 성공한2.0 Windows 빌드에서 EXE ZIP을 받아 압축을 푼다. 예전 EXE를 종료하고 창 제목의 버전을 확인한다.
2. 공식 Indi를 실행·로그인하고 EXE의 Windows 관리자 권한 확인을 처리한다. 앱이 Indi 로그인 암호를 저장하거나 자동 로그인하지 않는다.
3. `Indi 연결·종목 조회`를 눌러 종목 응답이 도착하는지 확인한다. `전략·운용한도` 탭에서 전략과 한도를 확인하고 `전략·운용한도 저장`을 누른다. 초기 한도는0이며 양수 한도를 저장해도 실주문 잠금은 해제되지 않는다.
4. 계좌번호·계좌암호를 프로그램에만 입력해 `실계좌 조회·감시`를 누른다. `실계좌 잔고·손익`과 `주문·체결` 탭에서 실제 보유 종목·수량·평균단가·현재가, 예수금과 주문 조회를 HTS와 비교한다. 서버 오류·빈 필드·미확인을 임의로0이나 정상 상태로 해석하지 않는다.
5. `부재중 운영 시작`을 누른다. 이후 `운영 중단` 또는 전략 저장은 계좌 세션도 해제하므로, 다시 운영하려면 계좌암호를 입력해 `실계좌 조회·감시`부터 재개한다.
6. 앱과 Indi를 켜두고 전원·네트워크가 유지되도록 한다. 실행 중 자동 절전 억제 요청은 중단·종료 시 해제된다. 수동 절전·덮개 닫기·OS 재시작을 자동 절전 억제로 막을 수 있다고 가정하지 않는다.

장외에 시작하면 한국시간 다음 평일09:00까지 기다리고, 장중에 시작하면 준비된 조회 상태에서 스캔을 진행한다. 한 차례 전체 스캔 완료20분 뒤 재스캔하며 운영시간은 평일09:00~15:20이다. 휴장일 달력과 실제 거래 세션은 아직 별도 검증이 필요하다.

## 퇴근 후 확인

- 화면에서 마지막 잔고·현재가·예수금·주문 조회 시각을 확인한다. 조회 시각과 거래소 체결시각은 다르다.
- 보유수량·평균단가·현재가와 평가금액을 HTS와 대조한다. 앱의 평가손익·수익률은 수수료·세금 제외 계산이며, 실현손익을 체결 증거 없이 만들어 표시하지 않는다.
- `보고서 폴더` 버튼으로 열린 현재 계좌의 `account-report-yyyyMMdd.csv`에서 날짜, 조회 시각, 실주문 잠금 상태, 계좌 평가와 주문 기록을 확인한다. 값이 없으면 `미확인`으로 남는지 확인한다. 기본 위치는 `%LOCALAPPDATA%\ShinhanNativeTrader\reports\<계좌키>`다.
- 대기 종목 수가 줄고, 전체 스캔 완료 후 다음 스캔이 중복 없이 시작되는지 확인한다. 후보가 없다는 이유로 가상 매수·체결을 생성하면 안 된다.
- 중단 또는 오류가 있으면 진단 로그의 마지막 요청번호·응답·실패 필드를 확인한다. 로그·보고서를 공유할 때 계좌·개인정보와 투자 정보는 필요한 부분만 남긴다.

## 실제 Windows에서 구분해 기록할 항목

| 확인 항목 | 현재 증거 / 남은 확인 |
| --- | --- |
| 종목 수신·파싱 | 사용자1.4.1/1.4.2에서 전체4,330건·일반주식2,401개 표시 확인. 필터 분류의 HTS 대조는 별도다. |
| 수동 현재가 | 사용자1.4.2에서 공개 종목005930의 조회 가격 수신·표시 확인. 거래시각 미제공 응답이며 HTS 일치 확인은 별도다. |
| 일봉 | 사용자1.4.2에서45개 반복 수신·분석 확인. OHLCV 값·수정주가·당일 봉 대조는 별도다. |
| 실제 잔고 | 사용자 화면에서2건 수신·표시 확인. 계좌번호·보유 종목·수량은 이 기록에 저장하지 않는다. 수량·평균단가·현재가의 HTS 일치 확인은 별도다. |
| 종목 발굴 | 사용자 화면에서262개 분석·2개 후보·2,138개 대기 확인. 전체 완료와 다음 날 재스캔 증거는 아니다. |
| 새 계좌 현금·주문 조회 |2.0에서 추가한 경로. 현재 서버의 필드·값·응답 완결성·수수료 및 예약금 반영을 확인해야 한다. |
| 부재중 일정 | 장외 대기→장중 시작→완료 후20분 재스캔→15:20 종료·보고서를 실제 PC에서 확인해야 한다. |
| 자격증명 수명 | 입력 후 화면 암호가 지워지고 실행 세션만 유지되는지, 운영 중단·전략 저장·앱 재시작 후 재인증이 필요한지 확인해야 한다. |
| 중단·연결 오류 | 응답 지연/단절·저장 오류·중단 후 주문이 재개되지 않고 보고서와 상태가 남는지 확인해야 한다. |
| 재시작 복구 | 미완료 실제 주문이 있으면 불명 상태로 차단되고 대사 없이 예약금/수량 해제·자동 재전송되지 않아야 한다. 실제 주문으로 시험한 결과는 없다. |
| 실제 주문·체결 | 현재 잠금 상태. 승인·메서드 호출·요청번호·주문 접수번호만으로 체결을 확정하지 않는다. 별도 검증 전 실제 주문을 시험하지 않는다. |

같은 시각의 기대값과 실제값, EXE 커밋·버전, 조회 TR·요청번호와 결과를 기록한다. 계좌번호·암호·실제 보유 명세는 GitHub 문서나 이슈에 포함하지 않는다. 현재 보고서와 로컬 계좌 화면은 투자 정보를 포함하므로 비공개로 관리한다.

## 실주문 검증의 경계

주문 코드는 공식 자료의 신규 `SABA101U1`, 정정·취소 `SABA102U1`에 맞춰 작성했지만 추가 입력의 기본값·최신 시장 라우팅 등 미확인 사항이 남아 있다. 현금100% 주문가능금액·종목별 가능수량, 실제 미체결·부분체결·정정·취소확정, 현물 AA/AD 이벤트와 재시작 후 대사가 검증되기 전에는 생산 주문 게이트를 열지 않는다. UI 한도나 부재중 설정으로 이를 우회하지 않는다.

CI의 가짜 전송·합성 COM·일정 및 저널 테스트는 위 상태 전이를 자동으로 검증하는 코드 증거다. 실제 신한 계좌에 주문·정정·취소를 전송한 증거는 아니다. 자세한 근거는 [주문 계약](INDI_LIVE_ORDER_CONTRACT.md), [조회 계약](INDI_QUERY_CONTRACT.md), [검증 보고서](../TEST_REPORT.txt)를 참조한다.
