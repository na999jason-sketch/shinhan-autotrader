# Windows 실계좌 운영 확인 — 2.1

**`실주문 운영 시작`을 누른 계좌에서는 조건을 통과한 실제 주문이 전송될 수 있다.** 앱 실행·계좌 조회·전체 스캔은 주문 시작 동작과 구분한다. 이 안내는 운영 절차이며 실제 신한 서버의 주문·체결 검증이 완료됐다는 보고가 아니다.

## 출근 전에

1. [PR #1](https://github.com/na999jason-sketch/shinhan-autotrader/pull/1)의 성공한2.1 Windows 빌드에서 EXE ZIP을 내려받아 압축을 푼다. 이전 EXE를 종료하고 창 제목의 버전을 확인한다.
2. `전략·운용한도`에서 전략과0원보다 큰 한도를 정하고 `전략·운용한도 저장`을 누른다. 이 값은 실제 증권사 잔고·현금100% 주문가능금액을 대신하지 않는다.
3. 공식 Indi를 실행·로그인하고 `Indi 연결·종목 조회`를 누른다. Windows 관리자 권한 확인은 OS가 처리한다.
4. 계좌번호·계좌암호를 프로그램에 입력하고 `실계좌 조회·감시`를 누른다. `실계좌 잔고·손익`과 `주문·체결`의 조회값·조회 시각을 확인한다. 이 단계에서는 주문 실행을 시작하지 않는다.
5. 해당 계좌로 자동 주문을 실행하려면 **`실주문 운영 시작`**을 누른다. 화면에 대상 거래일과 실주문 시작 상태가 표시된다. 장외에 누르면 다음 평일 장 운영시간까지 기다린다.
6. PC·Indi·앱을 켜두고 전원과 네트워크를 유지한다. 실행 중 자동 절전 억제는 수동 절전·덮개 닫기·재부팅을 막거나 인증 만료 후 자동 로그인하는 기능이 아니다.

평일09:00~15:20에 전체 종목의 일봉을 순차 검색하고, 전체 스캔 완료20분 후 다시 검색한다. 보유와 후보에는 실시간 시세를 등록한다. 모든 종목의 모든 틱을 동시에 수신하는 기능은 아니다. 기존 보유도 같은 손절·익절·추적손절 대상이며 개장 시 일괄 매도하지 않는다. 휴장일 달력은 미연동이다.

실주문 시작 상태는 한 계좌·한 거래일에 한정된다.15:20에 만료되면 추가 주문 전송을 중지하며 다음 거래일에는 다시 시작해야 한다. 만료 뒤 계좌 조회·실시간 수신·기존 주문 후속 체결 확인과 보고서는 계속한다.

**`운영 중단`·앱 종료·연결 단절은 이미 접수된 증권사 주문을 자동 취소하지 않는다.** 기존 미체결은15:20 이후에도 체결될 수 있으므로 주문의 취소·확정 상태는 HTS와 별도로 확인한다. 중단·전략 저장·재시작 뒤 다시 운영하려면 계좌 세션과 실주문 시작 상태를 다시 설정해야 한다.

## 퇴근 후

- `실계좌 잔고·손익`에서 수량·평균단가·현재가와 `매도판정`을 확인한다. 기존 보유와 새 보유 모두 같은 알고리즘으로 판단하며, 조건 미충족·시세/계좌 자료 부족은 대기로 표시한다.
- 평가손익·수익률은 수수료·세금 제외 계산이다. `실현손익(증권사 조회)`는 실제 응답값과 조회 시각이며 원천 거래일이 미확인인 값을 당일 손익으로 해석하지 않는다.
- `주문·체결`에서 접수·누적 체결·미체결·정정·취소 상태를 확인한다. 접수번호를 받은 사실만으로 체결 완료로 보지 않는다. 낯선 미체결이나 불명 주문이 있으면 자동 재전송 없이 대사 대기로 남아야 한다.
- `보고서 폴더`를 누르면 현재 계좌의 수신 자료를 즉시 CSV로 저장한 뒤 폴더를 연다. 화면의 `보고서 저장` 시각·파일명과 `account-report-yyyyMMdd.csv`의 대상 날짜·실제 조회 시각·운영 상태·주문과 손익을 확인한다. `.xlsx`가 아니라 엑셀로 열 수 있는 `.csv`다. 기본 위치는 `%LOCALAPPDATA%\ShinhanNativeTrader\reports\<계좌키>`다.
- 2.1.2부터 첫 계좌 응답 수신 시 저장을 시작하고 초기 잔고·현금·주문 응답을 반영한다. 이후 약5분마다 저장하며 조회 대기·주문 준비 상태도 저장 검사를 건너뛰지 않는다. 장외에도 동작한다. 계좌 응답을 아직 받지 않았다면 미수신 사유를 표시하고 빈 보고서를 만들지 않는다.
- 재시작 후 계좌 미조회 상태에서는 이전 보고서가 있는 폴더를 찾아 열고 `이전 보고서`로 표시한다. 이것으로 계좌를 연결하거나 새 보고서를 저장했다고 표시하지 않는다.
- `보고서 저장 실패`가 보이면 진단 로그의 실제 경로와 원인을 확인한다. Excel이 CSV를 열어 파일 교체를 막는 경우에는 CSV를 닫는다. 권한·디스크 문제도 확인한다. 실패를 성공으로 표시하지 않으며 기존의 정상 CSV는 보존한다. 저장 오류로 운영이 중단됐다면 원인 해결 후 앱을 다시 열어야 한다.
- 운영·주문이 대기했다면 진단 로그의 구체적인 사유를 확인한다. 현재 시세/거래일, 새로운 잔고·현금·주문 응답, 종목별 수량·금액, 미체결 대사 중 부족한 조건이 있으면 실제 전송되지 않는다.

## 실행 조건과 검증의 경계

실행 조건은 [현재 인터페이스 확인 기록](INDI_API_VERIFICATION.md)에 정리했다. 현재 버전은 상시 비활성화 상수를 사용하지 않으며, 사용자 시작 세션과 매 주문의 실제 응답·시세·수량·금액·대사·변경 여부를 검사한다. 이 검사는 전체 서버 계약이나 데이터 완결성이 독립적으로 인증됐다는 뜻이 아니다.

CI의 단위·가짜 전송·합성 COM·Windows UIPI·GUI 검증은 코드 증거다. 실제 신한 서버의 주문·체결과 수익 검증은 아직 수행하지 않았다. [실시간 계약](INDI_REALTIME_CONTRACT.md), [주문 계약](INDI_LIVE_ORDER_CONTRACT.md), [검증 보고서](../TEST_REPORT.txt)에 출처와 한계가 있다.
